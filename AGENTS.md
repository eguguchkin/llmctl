# llmctl — единый пульт управления LLM-движками (gufo / hipfire / halogen)

Одна машина — один активный движок. `lctl` — единственная точка управления:
жизненный цикл стека (preflight + GPU-prep → bootstrap → юниты → контейнер →
health/smoke), эксклюзивный переключатель движков, самолечение известных
аномалий. Жизненный цикл — в `core/` (движок-независимый, один источник);
движковая специфика — в адаптерах `engines/<имя>/`: профили, health-диалект,
метрики/watch-панели, doctor, пины, конфиг-ключи.

Родители-проекты — **самостоятельные** до миграции: gfctl (gufo),
hfctl (hipfire). Это источники приёмов и кода (порт «при касании»),
не зависимости. Третий движок **halogen — пилот границы core↔adapter**:
если адаптеру понадобилась правка ядра — граница спроектирована неверно.

Язык ответов — русский. На простых задачах — коротко и по существу;
подробность — для сложных тем и приёмок.

Development protocol: dev-flow

## Инварианты поставки (наследие hfctl/gfctl, обязательны)

- **И1 — голая Ubuntu одной командой**: `git clone && ./lctl start <engine>
  <profile>` (напр. `lctl start hipfire flash`). Обвязка сама ставит (идемпотентно, sudo точечно): podman,
  podman-compose, containers-storage, psmisc, curl + GPU-подготовку
  (группы render/video, limits.d memlock — только при наличии
  `/dev/kfd`/`/dev/dri`, честный «требуется перелогин»; не-GPU машина —
  info-пропуск).
- **И2 — сценарная приёмка без ручных корректировок**: пройденным считается
  только сценарий-последовательность команд `lctl` (+ диагностические чтения:
  podman ps/inspect, curl health, journalctl). Внеплановая ручная мутация =
  FAIL сценария + дефект в бэклог.
- **И3 — деплой/прогоны на машину всегда из GitHub**: клон на машине → pull;
  tar/cp из воркспейса запрещены (в т.ч. в EXP).

## Конвенции разработки

- Цикл: **architect (task.md) → developer → tester → reviewer**; код без
  контракта не пишется; машины из сабстейджей не трогаются (деплой —
  отдельное окно по GO пользователя).
- Батарея: `tests/run_checks.sh`, faux-подставки (systemctl/podman/id/flock),
  мутации по маркерам `# fix:<имя>` на КОПИЯХ дерева (bash -n мутанта
  пофайлово), счётчики фиксируются в отчётах.
- Известные уроки — переносить в ядро осознанно (реестр ниже): rootless-netns/AppArmor-pasta (обход CONTAINERS_CONF),
  card0↔card1 (recreate), bootstrap-guard×мигр-`.env` «курица-яйцо»
  (.env не «состояние», а воспроизводимый документ), flock-зомби
  (детект живого-но-зависшего держателя), честный off (явный podman stop).
